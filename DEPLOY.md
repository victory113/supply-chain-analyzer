# Deploying

Step by step, free tier, roughly 45 minutes the first time.

**End state:** a public URL you can put on a résumé, backed by real Postgres.

You'll create accounts on three services. All three have genuine free tiers —
no card required for Neon or Netlify; Render asks for one on some plans but the
free web service does not.

| Piece | Service | Why this one |
|---|---|---|
| Database | **Neon** | Free tier is persistent. Render's free Postgres is deleted after 30 days — useless for a portfolio link. |
| Backend | **Render** | Reads `render.yaml` directly. Free web services sleep after 15 min idle. |
| Frontend | **Netlify** | Free, reads `netlify.toml`, and proxies `/api` so there's no CORS to configure. |
| Cache | *(skipped)* | Optional. The app runs fine without Redis. Add Upstash later if you want. |

## Step 1. Database (Neon)

1. Go to **https://neon.tech** and sign up (GitHub login is easiest).
2. **Create a project.** Name it `supply-chain-analyzer`. Any region near you.
3. On the project dashboard find **Connection string**. Copy it.

It looks like:

```
postgresql://neondb_owner:npg_AbC123@ep-cool-name-12345.us-east-2.aws.neon.tech/neondb?sslmode=require&channel_binding=require
```

**Paste it somewhere safe — you need it in Step 2, and Neon only shows the
password once.**

> You do **not** need to edit this string. The app rewrites the driver and the
> `sslmode` parameter itself (`backend/app/core/config.py`), because asyncpg
> rejects both. That's what `tests/unit/test_dsn_normalization.py` covers.

## Step 2. Backend (Render)

1. Go to **https://render.com**, sign up, and connect your GitHub account.
2. **New → Blueprint.**
3. Pick the `supply-chain-analyzer` repo. Render finds `render.yaml` and shows
   one service: `sca-api`.
4. It will prompt for the values marked `sync: false`. Fill in:

   | Key | Value |
   |---|---|
   | `DATABASE_URL` | the Neon string from Step 1, pasted whole |
   | `ANTHROPIC_API_KEY` | your key from console.anthropic.com |
   | `REDIS_URL` | leave **empty** |
   | `CORS_ORIGINS` | leave **empty** |

   `SECRET_KEY` is generated by Render — don't touch it.

5. **Apply.** First build takes 5–10 minutes (it's building the Docker image).

*You should see:* the log end with `Application startup complete.` and the
service marked **Live**.

6. Copy your service URL — something like
   `https://sca-api-a1b2.onrender.com`.

7. **Test it.** Open `https://YOUR-SERVICE.onrender.com/api/v1/health` in a
   browser.

   *You should see:* `{"status":"ok","service":"Supply Chain Intelligence API",...}`

   Also try `/docs` for the full API reference.

### If the build fails

| Log says | Fix |
|---|---|
| `sh: 1: ...: not found` / `Exited with status 127` | The start command is being wrapped in a second shell. Render runs `dockerCommand` through one already, so `sh -c "a && b"` collapses into a single unfound program name. It should be `/app/docker-entrypoint.sh`. |
| The build log shows your new layers, but the runtime error is unchanged | Render **stored** `dockerCommand` on the service when the blueprint was first applied, and editing `render.yaml` does not clear it. Fix it in the dashboard: service → **Settings** → **Docker Command** → set to `/app/docker-entrypoint.sh` → Save. Same applies to any env var you set at blueprint-apply time. |
| `alembic.util.exc.CommandError` or connection refused | `DATABASE_URL` is wrong or incomplete. Re-copy from Neon — it's easy to miss the end of the string. |
| `password authentication failed` | Password got truncated on copy. Re-copy the whole line. |
| `No module named 'app'` | Docker context is wrong. Confirm `render.yaml` is at the repo root, unedited. |
| Build succeeds, health check fails | Check the service is listening on `$PORT` — the `dockerCommand` in `render.yaml` handles this. |

## Step 3. Point the frontend at the backend

Open `frontend/netlify.toml`. Find this:

```toml
[[redirects]]
  from = "/api/*"
  to = "https://YOUR-BACKEND-HOST/api/:splat"
  status = 200
  force = true
```

Replace `YOUR-BACKEND-HOST` with your Render hostname (no `https://`, no
trailing slash):

```toml
  to = "https://sca-api-a1b2.onrender.com/api/:splat"
```

Then commit and push:

```powershell
git add frontend/netlify.toml
git commit -m "chore: point the Netlify API proxy at the deployed backend"
git push
```

> **Why a proxy instead of calling Render directly?** It keeps every request
> same-origin, so the browser never sends a CORS preflight and you never have
> to maintain an allowed-origins list. It's also why the frontend code uses
> relative `/api` URLs everywhere.

## Step 4. Frontend (Netlify)

1. Go to **https://netlify.com**, sign up, connect GitHub.
2. **Add new site → Import an existing project → GitHub →**
   `supply-chain-analyzer`.
3. Netlify reads `netlify.toml`, so the build settings should already say:
   - Base directory: `frontend`
   - Build command: `npm run build`
   - Publish directory: `dist`

   If they're blank, type them in.
4. **Deploy.** Takes 2–3 minutes.

*You should see:* a URL like `https://cheerful-tanuki-1a2b3c.netlify.app`.

Rename it under **Site configuration → Change site name** to something you'd
put on a résumé — `victory-supply-chain`, say.

---

## Step 5. Test the live app

Open your Netlify URL.

1. Register an account.
2. Click **Try sample data**.

**Be patient on the first request.** Render's free tier sleeps after 15
minutes of inactivity, and waking it takes 30–60 seconds. During that window
the frontend shows a connection error. Reload and it works.

*Working means:* dashboard populates with KPIs, the risk gauge, the trend
chart, and the AI risk assessment a few seconds later.

## What "free" actually costs you

Be honest about these if someone asks — they're normal engineering tradeoffs,
not embarrassments.

| Limitation | Consequence | Fix |
|---|---|---|
| Render free tier sleeps after 15 min | First visit takes 30–60s | $7/mo, or a cron ping every 10 min |
| No Celery worker on free tier | Analysis runs in-process | Paid worker service; code already supports it |
| No Redis | No caching; every analytics call recomputes | Upstash free tier, set `REDIS_URL` |
| Neon free tier | 0.5 GB, autosuspends | Plenty for a demo |

Every one of these is a config change, not a code change. That's the point of
the design — and it's a good answer when someone asks what you'd do to scale it.

## Adding Redis later (optional, 5 minutes)

1. **https://upstash.com** → sign up → **Create Database** (Redis, free tier).
2. Copy the connection string starting `rediss://`.
3. In Render → your service → **Environment** → set `REDIS_URL` → **Save**.

The service redeploys and starts caching. Nothing else changes.
